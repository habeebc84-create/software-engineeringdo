# Experiment 12: Prioritizing Task Management System Requirements Using Moscow And Kano In Jira

**Tools Used:** Jira
**Course Outcome:** CO2

## Aim
To create the requirements of a Task Management System as Jira issues and prioritize them
using the MoSCoW and Kano models.

## Software / Tools Required
Jira Software (Cloud) – Scrum project

Web browser

## Theory
Prioritization techniques help the team decide which requirements give the most value. Two
complementary techniques are used here:

MoSCoW – classifies requirements as Must, Should, Could and Won’t have, based on
business necessity.

Kano model (Noriaki Kano, 1984) – classifies features by their effect on customer
satisfaction.
Kano Category
Description
Basic (Must-be)
Expected by users; absence causes dissatisfaction,
presence is taken for granted.
Performance (One-dimensional)
Satisfaction increases in proportion to how well it is
implemented.
Excitement (Attractive)
Unexpected features that delight users; absence causes
no dissatisfaction.
Indifferent
Users do not care either way.
Reverse
Presence causes dissatisfaction for some users.
In Jira the categories are recorded with labels (e.g. MoSCoW-Must, Kano-Basic) or with custom
fields, and can be used to filter the backlog.

## Viva Voce Questions
1. What is the Kano model?
Ans: A model that classifies features according to how they affect customer satisfaction.
2. Give an example of a Basic feature.
Ans: User login – users expect it to exist.
3. Give an example of an Excitement feature.
Ans: Automatic progress reports or smart reminders.
4. How can MoSCoW priority be stored in Jira?
Ans: Using labels, the Priority field or a custom select-list field.
5. Why use both MoSCoW and Kano?
Ans: MoSCoW captures business necessity while Kano captures customer satisfaction,
giving a balanced view.
