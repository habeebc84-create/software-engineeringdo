# Experiment 09: Creating A Scrum Project With Backlog And Sprint In Jira

**Tools Used:** Jira
**Course Outcome:** CO2

## Aim
To create a Scrum project in Jira, add user stories to the product backlog, plan a sprint, start the
sprint and track the work on the sprint board.

## Software / Tools Required
Jira Software (Cloud)

Web browser

Atlassian account

## Theory
Scrum is an Agile framework in which a cross-functional team delivers working software in
short, fixed iterations called sprints (usually 1–4 weeks).

Roles – Product Owner (owns the backlog), Scrum Master (facilitates the process) and
Development Team.

Artefacts – Product Backlog, Sprint Backlog and Increment.

Events – Sprint Planning, Daily Scrum (stand-up), Sprint Review and Sprint Retrospective.
In Jira a Scrum project offers a Backlog view (to create epics, stories, tasks and bugs and to
estimate them with story points), a sprint planning area, an active sprint board and reports such
as the Burndown chart and Velocity chart.

## Viva Voce Questions
1. What is a sprint?
Ans: A fixed time-box (1–4 weeks) during which a usable increment is produced.
2. What is a product backlog?
Ans: An ordered list of all features, enhancements and fixes needed for the product.
3. What is a story point?
Ans: A relative unit used to estimate the effort or complexity of a user story.
4. What is a burndown chart?
Ans: A graph of remaining work versus time in a sprint.
5. Who prioritises the product backlog?
Ans: The Product Owner.
